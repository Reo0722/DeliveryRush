# DeliveryRush 配達システム構築ガイド（UE5 Blueprint）

## 全体設計

この配達システムは以下の4つの要素で構成されます。

1. **データ定義**（DataTable / Struct） — 商品・店舗・配達先の情報
2. **依頼管理**（GameInstanceまたはGameMode） — 依頼の生成・状態管理
3. **店舗システム**（Actor / Trigger） — 商品の陳列・会計処理
4. **配達完了判定**（Actor / Trigger） — 配達先での受け渡し・評価

---

## ステップ1：データ構造を作る（Struct と DataTable）

まずゲーム内で使うデータの「型」を定義します。UE5では **Struct（構造体）** でデータの型を作り、**DataTable** でそのデータの一覧表を作ります。

### 1-1. 商品Structを作る

**操作手順：**
1. コンテンツブラウザで右クリック → 「Blueprints」→「Structure」を選択
2. 名前を `S_Item`（商品構造体）にする
3. ダブルクリックで開き、以下の変数を追加する：

| 変数名 | 型 | 説明 |
|--------|-----|------|
| ItemID | Name | 商品の一意な識別子（例：`Onigiri_Salmon`） |
| ItemName | Text | 表示名（例：「鮭おにぎり」） |
| Price | Integer | 価格 |
| StoreID | Name | どの店に置いてあるか（`Store_A` / `Store_B` / `Both`） |
| ItemMesh | Static Mesh（ソフト参照） | 3D表示用のメッシュ（後で設定、最初はなくてOK） |
| ItemIcon | Texture2D（ソフト参照） | UI表示用アイコン（後で設定） |

> **Struct の変数追加方法：** Structエディタ上部の「Add Variable」ボタンを押し、名前と型を設定します。型は右側のドロップダウンから選びます。

### 1-2. 配達先Structを作る

同様に `S_DeliveryTarget` を作成：

| 変数名 | 型 | 説明 |
|--------|-----|------|
| TargetID | Name | 配達先の識別子（例：`House_A`） |
| TargetName | Text | 表示名（例：「田中さんの家」） |
| Location | Vector | ワールド上の座標（ナビ用） |
| NPCClass | Soft Class Reference (Actor) | その家にいるNPCのBPクラス |

### 1-3. 依頼Structを作る

`S_DeliveryOrder`（1件の依頼を表す）：

| 変数名 | 型 | 説明 |
|--------|-----|------|
| OrderID | Integer | 依頼の通し番号 |
| RequestedItems | Array of S_Item | 注文された商品リスト |
| TargetInfo | S_DeliveryTarget | 配達先情報 |
| OrderStatus | Enum（後述） | 依頼の進行状態 |

### 1-4. 依頼状態のEnumを作る

コンテンツブラウザで右クリック →「Blueprints」→「Enumeration」→ 名前を `E_OrderStatus`：

- `Pending` — 依頼表示中（まだ受けていない）
- `Accepted` — 受注済み（買い物へ）
- `Shopping` — 買い物中
- `Delivering` — 配達中
- `Completed` — 完了

### 1-5. DataTableを作る

1. コンテンツブラウザで右クリック →「Miscellaneous」→「Data Table」
2. Row Structureに `S_Item` を選択 → 名前を `DT_Items`
3. 開いて行を追加し、商品データを入力していく

**商品例（仮データ）：**

| RowName | ItemName | Price | StoreID |
|---------|----------|-------|---------|
| Onigiri_Salmon | 鮭おにぎり | 150 | Both |
| Bento_Nori | のり弁当 | 450 | Store_A |
| Drink_Tea | お茶500ml | 130 | Both |
| Magazine_Weekly | 週刊誌 | 350 | Store_B |
| Bandage | ばんそうこう | 200 | Store_A |
| Notebook | ノート | 120 | Store_B |
| Sandwich_Egg | たまごサンド | 280 | Both |
| Battery_AA | 単三電池 | 300 | Store_B |

同様に `DT_DeliveryTargets`（S_DeliveryTargetのDataTable）も作ります。

## ステップ2：依頼管理システムを作る（GameInstance）

依頼の生成・管理はレベルが変わっても消えない **GameInstance** に置きます。

### 2-1. GameInstanceのBPを作る

1. コンテンツブラウザで右クリック →「Blueprint Class」→ 親クラスに `GameInstance` を選択
2. 名前を `BP_DeliveryGameInstance` にする
3. Project Settings → Maps & Modes → Game Instance Class に設定する

### 2-2. 変数を追加

BP_DeliveryGameInstance を開き、以下の変数を作成：

| 変数名 | 型 | 説明 |
|--------|-----|------|
| CurrentOrder | S_DeliveryOrder | 現在の依頼 |
| bHasActiveOrder | Boolean | 依頼進行中かどうか |
| bIsFirstOrder | Boolean（初期値true） | 最初の依頼かどうか |
| CompletedOrders | Integer | 完了した依頼数 |
| ItemTable | DataTable Reference | DT_Items への参照 |
| TargetTable | DataTable Reference | DT_DeliveryTargets への参照 |
| PlayerInventory | Array of S_Item | プレイヤーが今持っている商品 |

### 2-3. 依頼生成関数を作る

**関数名：`GenerateNewOrder`**

処理の流れ（Blueprintノードで組む）：

```
1. DT_Items から Get Data Table Row Names で全行名を取得
2. その中からランダムに 1〜3個 選ぶ（Array → Shuffle → 先頭N個取る）
   - StoreID でフィルタする必要はない（どの店かは依頼には関係ない）
3. DT_DeliveryTargets からランダムに1件選ぶ
4. S_DeliveryOrder を構築して CurrentOrder にセット
5. bHasActiveOrder = true
6. UIに通知するイベントディスパッチャー（OnNewOrder）を呼ぶ
```

**Blueprint での具体的な組み方：**

1. 「Get Data Table Row Names」ノードを配置し、DT_Items を接続
2. 返ってきた Name 配列を「Shuffle」してランダム化
3. 「Get Data Table Row」で先頭1〜3件の行データ（S_Item）を取得
4. 同様にDT_DeliveryTargetsからランダム1件取得
5. 「Make S_DeliveryOrder」で依頼を構築
6. 変数 CurrentOrder に Set

### 2-4. 依頼タイマーを作る

**関数名：`StartOrderTimer`**

```
1. bIsFirstOrder を確認
2. true の場合：
   - Random Float in Range (1.0 〜 10.0) で待ち時間を決める
   - Set Timer by Event でその秒数後に GenerateNewOrder を呼ぶ
3. false の場合（2回目以降）：
   - 依頼完了直後に直接 GenerateNewOrder を呼ぶ（タイマー不要）
```

**Set Timer by Event の使い方：**
1. Custom Eventを作る（例：`OnTimerFired`）
2. 「Set Timer by Event」ノードを配置
3. Event ピンに OnTimerFired を接続
4. Time ピンに Random Float の結果を接続
5. OnTimerFired の中で GenerateNewOrder を呼ぶ

## ステップ3：依頼表示UI（Widget）

### 3-1. Widget Blueprintを作る

1. コンテンツブラウザで右クリック →「User Interface」→「Widget Blueprint」
2. 名前を `WBP_OrderNotification` にする

### 3-2. レイアウト設計

Designerタブで以下を配置：

- **Canvas Panel**（ルート）
  - **Vertical Box**（右下にアンカー設定）— Anchor: Bottom-Right
    - **Text**：「新しい依頼！」
    - **Vertical Box**（商品リスト用）
      - **Text**（各商品名を表示）— `ItemListText` という名前にする
    - **Text**：配達先名 — `TargetNameText`
    - **Button** + **Text**：「依頼を受ける」

> **Anchorの設定方法：** Vertical Boxを選択 → Details パネル → Anchors のドロップダウンから右下のアイコンを選択。Position X/Y で画面端からの距離を調整。

### 3-3. データバインド

Graph タブに移動：

1. **Event Construct**（Widget生成時に呼ばれる）で GameInstance を取得
2. GameInstance の `OnNewOrder` イベントディスパッチャーに Bind する
3. バインドされたイベント内で：
   - CurrentOrder から RequestedItems を取得
   - For Each Loop で商品名を文字列に結合
   - ItemListText と TargetNameText を更新
   - Widget を Visible にする（普段は Hidden）

### 3-4. UIをPlayerControllerから表示する

PlayerController（またはHUD）の BeginPlay で：
1. `Create Widget` ノードで WBP_OrderNotification を生成
2. `Add to Viewport` でHUDに追加
3. 初期状態は `Set Visibility` → Hidden

## ステップ4：店舗システム

### 4-1. 商品アクター（BP_ShopItem）を作る

1. 新規Blueprint → 親クラス `Actor`  → 名前 `BP_ShopItem`
2. コンポーネントを追加：
   - **Static Mesh Component**：商品の見た目（仮でCubeでOK）
   - **Box Collision**：プレイヤーが近づいた時の検知用
   - **Widget Component**（オプション）：商品名を頭上に表示

3. 変数を追加：
   - `ItemData`（S_Item型）— この商品の情報。Instance Editable にチェック → レベルに置いた時に個別設定可能に
   - `bIsHighlighted`（Boolean）— 今の依頼で必要な商品か

4. **Begin Play** で：
   - GameInstanceのCurrentOrderをチェック
   - RequestedItems に自分の ItemData.ItemID が含まれていたら
   - メッシュのマテリアルを光らせる（Set Material → 発光マテリアル）
   - bIsHighlighted = true

5. **インタラクション**（拾う）：
   - Box Collision の On Component Begin Overlap を使う
   - プレイヤーが重なったら、インタラクトキー（例：E）の入力を待つ
   - Eキー押下 → GameInstance の PlayerInventory に ItemData を Add
   - この Actor を Destroy（または Hidden にする）

> **入力の取り方：** Enhanced Input System を使っている場合は、Input Action を作成し、Input Mapping Context に割り当てます。既にプレイヤー動作が作られているなら、同じ仕組みに追加するだけです。

### 4-2. レジアクター（BP_Register）を作る

1. 新規Blueprint → Actor → 名前 `BP_Register`
2. コンポーネント：
   - Static Mesh（レジの見た目）
   - Box Collision（会計エリア）

3. 変数：
   - `StoreID`（Name型）— このレジがどの店か（Instance Editable）

4. **On Component Begin Overlap**：
   - GameInstance の PlayerInventory 内の全アイテムについて
   - 各アイテムの `bIsPaid`（会計済みフラグ）を true にする
   - 「会計完了」のUIやサウンドを再生
   - OrderStatus を `Delivering` に変更

> **bIsPaid について：** S_Item に `bIsPaid`（Boolean、初期値false）を追加してください。レジを通すとtrueになります。

### 4-3. 店の出入り口ブロック（BP_StoreExit）

未会計商品を持っていると出られない仕組み：

1. 新規Blueprint → Actor → 名前 `BP_StoreExit`
2. コンポーネント：
   - Box Collision（出口に設置）
   - Blocking Volume または移動不可の壁（動的に切り替え）

3. ロジック（On Component Begin Overlap）：
   ```
   GameInstance の PlayerInventory を取得
   → 各アイテムの bIsPaid をチェック
   → 全て true なら通過許可（Collision を NoCollision に変更 or 壁を非表示）
   → 1つでも false なら「未会計の商品があります！」UI表示 & 通過拒否
   ```

**実装のコツ：** Box Collisionとは別に、**BlockingVolume（またはInvisible Wall）** をもう1つ用意し、そのCollisionを動的にON/OFFするのが簡単です。`Set Collision Enabled` ノードで `No Collision` / `Query and Physics` を切り替えます。

## ステップ5：配達完了システム

### 5-1. 配達先アクター（BP_DeliveryHouse）を作る

1. 新規Blueprint → Actor → 名前 `BP_DeliveryHouse`
2. コンポーネント：
   - Box Collision（家の入り口）
   - Widget Component（頭上に依頼者名を表示、依頼中のみ表示）

3. 変数：
   - `HouseID`（Name型、Instance Editable）
   - `bIsActiveTarget`（Boolean）— 現在の配達先か

4. ロジック：
   - GameInstance の CurrentOrder.TargetInfo.TargetID と自分の HouseID を比較
   - 一致したら bIsActiveTarget = true にして、Widgetを表示（目印）

### 5-2. 依頼者NPC（BP_Requester）を作る

1. 新規Blueprint → Actor or Character → 名前 `BP_Requester`
2. 家の中に配置
3. Box Collision でプレイヤー接近を検知

4. **インタラクト時の処理：**
   ```
   1. GameInstance.CurrentOrder.RequestedItems を取得
   2. GameInstance.PlayerInventory と照合
   3. 全ての RequestedItems が PlayerInventory に含まれていればOK
      → 「ありがとう！」UI表示
      → 仮評価（例：ランダムで星3〜5）を表示
      → PlayerInventory をクリア
      → bHasActiveOrder = false
      → bIsFirstOrder = false
      → CompletedOrders++
      → すぐに GenerateNewOrder を呼ぶ（2回目以降はタイマーなし）
   4. 不足があれば
      → 「○○が足りません」UI表示
   ```

**照合ロジックの組み方（Blueprint）：**
1. RequestedItems の For Each Loop
2. 各アイテムの ItemID で PlayerInventory を検索（Find ノード）
3. 見つからなかったら `bAllFound = false` にしてBreak
4. 全部見つかったら完了処理へ

## ステップ6：全体の流れをつなげる

### ゲーム開始時（GameModeまたはPlayerController の BeginPlay）：

```
1. GameInstance を Get する
2. GameInstance の StartOrderTimer() を呼ぶ
3. UI Widget を作成して Viewport に追加
```

### 依頼の一連の流れ：

```
[開始] 
  ↓ ランダム秒待機（初回のみ）
[依頼生成] → UI右下に表示
  ↓ プレイヤーが依頼を確認
[買い物] → 該当店舗へ移動 → 強調表示された商品を拾う
  ↓ レジへ
[会計] → PlayerInventory の商品が会計済みに
  ↓ 店を出る（未会計チェック）
[配達] → 依頼者の家へ移動
  ↓ NPCに話しかける
[照合] → 商品チェック → 評価付与
  ↓
[完了] → Inventory クリア → 即座に次の依頼生成
  ↓
[繰り返し]（2回目以降はタイマーなし）
```

## 推奨する作業順序

1. **Struct と Enum を全部作る**（データの型定義）
2. **DataTable を作ってテストデータを入れる**（商品5〜8個、配達先3軒）
3. **BP_DeliveryGameInstance を作る**（依頼生成ロジック）
4. **WBP_OrderNotification を作る**（依頼がUIに出るか確認）
5. **BP_ShopItem を作る**（商品を拾えるか確認）
6. **BP_Register を作る**（会計処理）
7. **BP_StoreExit を作る**（未会計チェック）
8. **BP_DeliveryHouse + BP_Requester を作る**（配達完了）
9. **全体テスト** — 一連の流れが回るか確認
